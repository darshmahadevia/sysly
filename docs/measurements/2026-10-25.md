# Foreground measurements, October 25, 2026

Five fresh native Overview sessions on an Apple M4 Mac with 10 cores, 16 GiB RAM, and macOS 27.0.1 used a median 2.73% of one core and 264.7 MiB of physical footprint.

| Process measure | Median across sessions | Session range |
| --- | ---: | ---: |
| CPU | 2.73 % of one core | 2.64 to 2.85 % of one core |
| Physical footprint | 264.74 MiB | 256.63 to 266.70 MiB |
| RSS | 134.08 MiB | 129.53 to 134.16 MiB |

## Method and checks

Each session launches the optimized release executable with an isolated default settings directory and a 1320 by 900 point visible Overview window. Charts use the default sample-driven mode. Twenty seconds of warmup includes the resource reader's settling time. Each session then collects five 5-second windows, giving 25 accepted observation windows across five processes.

The native helper checks actual window visibility and foreground state. CPU time comes from native per-process counters and must agree with `ps`. The reader rejects lost-focus windows rather than count background time as foreground time. There were 0 rejected windows across this run. The report retains window bounds, host load, binary hash, per-window counters, and a native Overview capture. The retained capture was inspected to confirm that the real dashboard rendered.

The separate [collector check](2026-10-25/metrics-verification.json) verifies real CPU workload detection, physical memory and core counts against macOS, and an actual 16 MiB loopback transfer. It runs outside the overhead measurement.

## Interpretation and limits

These are absolute process observations under the recorded background load. No baseline build was rerun, so this measurement establishes no new speedup. The earlier before/after comparison in [performance.md](../performance.md) remains a separate historical result.

CPU is percent of one core, not percent of total machine capacity. Physical footprint is a macOS process accounting measure. RSS includes shared resident pages. Neither is Rust heap size. The results cover short sessions with partially filled history, not sustained maximum-history use, peak memory, or a leak test. Other user applications and macOS services remained active.

## Reproduce

```sh
cargo build --release --locked
swiftc scripts/ui.swift -o target/sysly-ui
python3 scripts/benchmark_foreground.py --output .audit/my-foreground-run
python3 scripts/verify_metrics.py
```

Use a fresh output directory. The native helper needs macOS automation, Accessibility, and screen capture permissions. Stop other Sysly instances and unrelated builds before measurement.
